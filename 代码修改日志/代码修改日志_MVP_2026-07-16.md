## 一、逐项完成情况

### G1 事件归并引擎 · `engine/merge.ts`
多维匹配评分（空间 0.35 + 时间 0.25 + 类型 0.25 + 方向 0.15）→ 三档处置（auto/caseLink/separate）；语义关键字段（伤亡/车辆/危化品）冲突强制拆分；并案组位置漂移 >1km 由 `groupDivergence` 监控。S0 双源归并改由本引擎评分（不再脚本写死）。

### G2 跨事件冲突校验 + 变长遍历 · `engine/conflictCheck.ts` · `engine/traversal.ts`
- 冲突校验：承接路径反查活跃拥堵事件，比较 `T_conflict`（B 队尾覆盖汇入区）与 `T_arrive`（A 分流到达），重叠即裁剪。**修正 demo-spec §5.4 倒装的重叠不等式**（按附录 A 案例一正确语义 `T_conflict ≥ T_arrive − 缓冲`），并含活跃实例锚点索引 `Map<road:kpBucket, eventId[]>`。
- 变长遍历：沿上游枢纽回溯（深度 2），命中「当前分流承接线经过枢纽下游交叉线」→ 自引用冲突 + 行动窗口。
- 单测锁定 S1（w=7.55、T_conflict≈24、T_arrive=18）与 S5（w=9.8、T=35.5）锚点。

### G3 条件求值器 · `engine/conditions.ts`
由事件属性 + 环境 + 时钟求值条件集（危化品/隧道/团雾/夜间/设备离线），派生边加权（团雾 ×2.2）与措施约束（雾区内禁设封道执行点）。S3 条件集改由引擎求值。封道点锚点（K1169.5→VMS-05@K1168）由既有模板锁定。

### G4 资源链推理 · `engine/resourceChain.ts`
从 store 抽出「占用方事件 → 剩余作业 + 转场」ETA 权衡为纯函数；`resolveResourceChain` 给出候选与推荐。锁定 S2（W-01 等待 41min 优于 W-EX 48min）。

### G5 事件接入 · `engine/ingest.ts` · `components/RuntimeBar.tsx`
运行模式事件录入表单 + 模拟事件源；接入管道 = 归并判定 → 五步推理 → 预案 → 条件 → 分流冲突自动裁剪。校验桩号/车道/流量。

### G6 确认时效 · `engine/confirmTiming.ts` · `components/TodoQueue.tsx`
控制类待办真实倒计时（目标 ≤3min）、超时/升级态；≥6min 触发升级横幅 + 最小安全动作集留痕（仅实况类自动执行，控制类维持待确认）；打回入口。

### G7 持久化与审计 · `services/persistence.ts` · `domain/audit.ts`
审计流「只增不改」+ 运行世界快照，**localStorage 同步实现**（SPEC-DEVIATION：SRS D1 建议 IndexedDB，单机演示规模改同步以简化 store 并规避异步复杂度），不可用回退内存并上报；快照支持刷新恢复「继续处置」。演示模式不写审计库。

### G8 图就绪数据集 · `engine/datasetBuilder.ts` · `domain/dataset.ts`
六段结构 event/context/event_logic/plan/label/feedback；演化链候选由推理轨迹事理边预填；JSONL 与审计 JSON 导出。

### G9 LLM 通道 · `services/llm.ts`
OpenAI 兼容端点 + JSON schema 校验 + **值级溯源比对**（桩号/资源 ID/ETA 归一化后须落引擎白名单，越界即拒绝回退模板）；配置仅存 localStorage；演示模式永不调用。

### G10 作废与证伪 · store `voidPlan/falsifyEvent/rejectMeasure`
预案作废（必填理由，人工触发）、事件证伪（感知误报 → 作废 + 归档）、措施打回（理由入数据集 feedback），全部入审计流。

### G11 全网态势 · `components/RuntimeBar.tsx` · `components/CongestionGrid.tsx`
运行模式并发 ≥5 起；活跃事件列表（含作废/证伪）；拥堵网格演示保持 2 行、运行模式支持多起并发（可滚动）。
