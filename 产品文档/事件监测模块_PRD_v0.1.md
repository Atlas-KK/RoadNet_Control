## 3. 项目背景

现有系统已形成“事件接入—归并—图谱推理—交通流计算—预案生成—人工复核—指令下发—执行跟踪—终报审计”的智能管控闭环，但事件主要由演示案例或人工上报直接进入研判，缺少对视频 AI 等数据源产生的原始告警进行持续接收、去重聚合、人工核实、等级判定和接管移交的前置业务层。

本模块在现有智能管控前增加事件监测域，以 AI 视频事件监测为核心工作入口，把算法告警转化为可信监测事件；一般事件在监测模块内持续跟踪并关闭，严重事件通过标准接管契约进入智能管控。

## 4. 建设目标

1. 建立原始告警、监测事件、管控事件三层业务模型。
2. 建立以视频证据为核心的监控员核实工作台。
3. 支持告警去重、聚合、冲突标记、误报和订正留痕。
4. 建立 L1～L4 内部监测等级及分级核实时限。
5. 实现 L3 人工接管、人工确认 L4 后自动接管。
6. 实现事件监测与智能管控之间的幂等接管和状态回写。
7. 提供 GIS 事件空间分布与聚集态势大屏。
8. 在无真实后端和真实算法接口时，以统一模拟适配器完成可运行 MVP。

本期核心成功标准：完成“模拟视频告警→聚合→核实→分级→一般事件闭环/严重事件接管→智能管控回写”的可重复演示链路。

## 5. 产品定位

```text
事件监测：把 AI 告警转化为可信事件
智能管控：把严重事件转化为可执行处置
```

事件监测负责发现、聚合、核实、分级、持续观察、一般事件解除与关闭，以及严重事件接管；智能管控负责推理计算、预案生成、复核下发、执行跟踪和处置关闭。

监测等级仅用于内部排序、核实和接管决策，不等同于法定事故等级或应急响应等级。

## 6. 用户角色与使用场景

| 角色 | 核心职责 | 数据范围 |
| --- | --- | --- |
| 路网监测员 | 查看告警、开始核实、确认/误报、订正、持续观察、发起 L3 接管 | 授权路段和设施 |
| 监控班长 | 超时督办、任务转交、L3/L4 复核、L4 持续观察审批、接管异常处理 | 本机构全部授权范围 |
| 指挥调度人员 | 接收管控事件、研判、预案、指令及关闭 | 接管至本级的事件 |
| 系统管理员 | 数据源、设备、规则和权限配置 | 配置权限范围；无业务核实权 |

跨区域事件设置一个主责机构和多个协同机构。主责机构负责核实结论、等级和接管；协同机构只能补充证据。主责变更须由监控班长操作并留痕。

## 7. 现状分析与可复用能力

### 7.1 可复用能力

- `App.tsx`：现有单页工作台入口，可扩展一级模块容器。
- `PanelFrame`、`FullscreenPanel`：复用面板外壳和全屏交互。
- `GisNetworkMap`及 `src/gis`：复用高德地图加载、路网、点线面覆盖物、聚焦和主题。
- `MonitorPanel/MonitorDrawer`：复用监控素材展示结构。
- `domain/event.ts`：作为接管后 ControlEvent 的现有领域基础。
- `engine/ingest.ts`、`merge.ts`、`severity.ts`：复用标准化、三档归并和等级计算思想。
- 现有推理、交通流、预案、待办、执行和终报引擎：在接管成功后继续使用。
- `services/persistence.ts`：需从 localStorage 业务持久化扩展为 IndexedDB 模拟业务存储。

### 7.2 现状差距

- 当前无原始视频告警对象和持续告警流。
- 当前事件上报后直接进入智能管控，无独立核实和接管阶段。
- 当前事件类型不足以覆盖行人、逆行、倒车、抛洒物及专业设施异常。
- 当前“基础设施监测”用于指令执行反馈，不等于异常事件发现。
- 当前现场图片和视频属于演示素材，不是真实视频流。
- MVP 规格建议 IndexedDB，当前业务持久化主要为 localStorage，存在规格偏差。

## 9. 名词与术语

| 术语 | 定义 |
| --- | --- |
| Alarm | 某一来源在某一时间产生的一次原始发现，原则上只增不改 |
| MonitoringEvent | 一条或多条 Alarm 去重聚合后形成的待核实或已确认监测事件 |
| ControlEvent | 智能管控接收后建立的独立处置实例 |
| 建议等级 | AI 和规则根据当前证据计算的内部风险建议 |
| 确认等级 | 监控员核实后确认的内部风险等级 |
| 持续观察 | 信息不足时的核实子模式，事件仍处于核实中 |
| 接管 | 创建关联 ControlEvent 并交由智能管控研判处置 |
| 接管快照 | 发起接管时不可变的已知事实、上下文和证据摘要 |
| 模拟数据 | 由本地案例或模拟适配器产生、非生产系统采集的数据 |

## 10. 总体业务流程

```text
视频 AI / 人工 / 交通运行 / 专业平台
                ↓
          原始告警标准化
                ↓
       精确去重与候选事件聚合
                ↓
          MonitoringEvent
                ↓
        监控员查看视频并核实
        ├─ 误报 → 留痕关闭
        ├─ 信息不足 → 持续观察 → 再核实
        └─ 确认 → 人工确认等级
                    ├─ L1/L2 → 持续监测 → 解除 → 关闭
                    ├─ L3满足规则 → 人工发起接管
                    └─ 人工确认L4 → 自动发起接管
                                      ↓
                               ControlEvent
                                      ↓
                         研判/预案/复核/执行/关闭
                                      ↓
                              状态回写事件监测
```

## 12. 页面结构与导航设计

一级导航为“事件监测/智能管控”，默认进入“事件监测—视频事件监测”。事件监测内部提供“视频事件监测/GIS态势感知”。刷新恢复原模块和视图；切换保留筛选、选中事件、滚动位置和地图视角。

视频事件监测采用“指标—筛选—卡片网格”结构。1920px 每行 4 张、1440/1366px 每行 3 张、1280px 每行 2 张；1180px 以下详情切换全屏，手机端不验收。

核实详情使用页面宽度 60%～70%的右侧抽屉并支持全屏。GIS 为独立大屏视图，不与视频列表固定三栏同屏。

## 15. GIS事件态势

### FR-EM-008 GIS事件态势

| 项目 | 需求 |
| --- | --- |
| 用户故事 | 作为监控员，我需要查看事件空间分布、高发区域和严重事件位置。 |
| 使用前提 | 监测事件包含有效空间位置；GIS 服务可用或可降级。 |
| 触发入口 | “GIS态势感知”、事件卡片“地图定位”。 |
| 主流程 | 地图展示事件点和聚合；选择点位显示摘要；可跳转视频核实。 |

| 输入 | MonitoringEvent 位置、类型、等级、状态和筛选条件。 |
| 输出 | 点位、聚合、热区及空间统计。 |
| 状态变化 | 地图选择仅更新选中事件；不修改业务状态。 |

| 权限 | 仅展示授权范围内事件和设施。 |
| 留痕 | 地图查看不审计；打开受限证据需审计。 |
| 验收 | 视频卡片可定位地图；GIS可返回原卡片；1000点位聚合可用。 |
| 影响模块 | GIS地图、覆盖物、弹窗和页面状态。 |
| 建议复用 | `GisNetworkMap`、`mapOverlays`、`incidentPopup`、地图主题。 |

## 18. 事件核实与状态流转

### FR-EM-006 核实任务、状态机与计时

| 项目 | 需求 |
| --- | --- |
| 用户故事 | 作为监控班组，我需要避免重复核实并保证高风险事件及时响应。 |
| 使用前提 | MonitoringEvent 已建立且未关闭。 |

## 21. 与智能管控模块的衔接

保留现有五个案例、人工应急直报、归并、推理、计算、预案、待办和审计流程。在智能管控现有事件接入前增加：

```text
HandoffRequest→校验→事件类型映射→ControlEvent→现有研判管线
```

应急直报需注明“绕过监测核实直接进入智能管控”，并进行重复事件检查。已有专属规则的类型进入现有推理；未覆盖的新类型进入“通用安全研判”，明确需要人工补充措施，不得伪造专业结论。

## 24. 接口及实时通信需求

生产目标采用 REST 查询/操作和 WebSocket 推送。推送消息至少包含 `messageId`、`eventType`、`entityType`、`entityId`、`entityVersion`、`occurredAt`、`serverTime`、`correlationId`和 payload。

本期实现统一 `MonitoringSourceAdapter`，页面只依赖适配器，不直接依赖案例定时器。WebSocket断开后生产目标降级为 REST 增量轮询；恢复后按游标补拉。

接口最少覆盖：列表、详情、证据授权、开始/释放核实、提交结果、持续观察、订正、接管、状态查询、增量补拉、审计和导出。

## 26. 异常、空状态与降级设计

- 无事件：展示“当前筛选条件下暂无事件”，提供重置筛选。
- 无权限：展示授权范围说明，不显示敏感数据。
- WebSocket断开：显示离线，转增量轮询，恢复后补拉。
- GIS失败：视频列表和核实仍可用。
- 视频失败：展示关键帧、算法信息和文字证据。
- AI服务中断：保留人工上报和历史核实。
- 接管服务失败：保留核实结果和接管失败状态。
- 证据过期：显示“已归档或不可在线访问”。
- 缓存失败：提示“当前数据仅保存在内存”。
- 版本冲突：展示字段差异，禁止旧版本覆盖。
- 大量重复告警：更新聚合数量，不重复发声。

## 29. 验收标准

1. **Given** 同一来源、同一告警ID重复发送10次，**When** 系统接收，**Then** 只保留一个有效Alarm并记录重复次数。
2. **Given** 同一摄像机短时间连续检测同一异常，**When** 聚合评分≥0.75，**Then** 只生成一个MonitoringEvent卡片。
3. **Given** 用户仅打开详情，**When** 未点击开始核实，**Then** 事件不进入核实中且不建立占用。
4. **Given** 某事件已被用户A核实，**When** 用户B尝试提交，**Then** 系统拒绝并显示当前核实人。
5. **Given** 证据不足，**When** 提交持续观察，**Then** 释放占用、设置复核时间并保留核实中主状态。
6. **Given** 持续观察事件收到新证据，**When** 消息到达，**Then** 事件立即置顶并标记待重新核实。
7. **Given** AI建议L3而人工确认为L2，**When** 提交，**Then** 两个等级分别保存且调整理由可追溯。
8. **Given** L4事件申请误报或降级，**When** 无班长复核，**Then** 状态不得生效。
9. **Given** 已确认L3满足接管规则，**When** 系统求值，**Then** 展示逐条依据但不自动接管。
10. **Given** 人工确认L4，**When** 核实提交成功，**Then** 系统自动发起接管但不自动下发控制措施。
11. **Given** 同一接管请求重复点击并发生重试，**When** 智能管控接收，**Then** 只产生一个有效ControlEvent。
12. **Given** 接管成功，**When** 用户留在监测模块，**Then** MonitoringEvent仍保留并显示ControlEvent关联和次级状态。
13. **Given** 智能管控状态变化，**When** 回写到达，**Then** 监测卡片和关联处置更新且不覆盖监测事实。
14. **Given** 已接管事件，**When** 监控员尝试直接误报或关闭，**Then** 系统拒绝并引导提交订正。
15. **Given** 视频加载失败，**When** 打开详情，**Then** 降级展示关键帧且仍可完成核实。
16. **Given** GIS加载失败，**When** 用户进入视频监测，**Then** 列表、详情和核实不受影响。
17. **Given** 1000条告警和200起活跃事件，**When** 执行组合筛选，**Then** 结果在500ms内更新。
18. **Given** 页面持续运行2小时，**When** 模拟流持续推送，**Then** 页面无崩溃且无明显持续内存增长。
19. **Given** 任一关键业务操作，**When** 操作成功或失败，**Then** 生成包含操作人、时间、对象、前后版本和原因的审计记录。
20. **Given** 模拟数据，**When** 在卡片、详情或GIS展示，**Then** 均可识别其模拟属性。

## 30. 典型验收场景

1. **重复异常停车**：12条告警聚合为1起L2事件，车辆驶离后解除并关闭。
2. **行人闯入误报**：查看视频后判定阴影/标识误报，保留Alarm并回写算法标签。
3. **抛洒物持续观察**：首次信息不足，3分钟复核前新证据到达，确认L3并建议接管。
4. **隧道事故L3接管**：多源证据、两车道受阻，人工接管后进入现有推理预案并回写状态。
5. **隧道火灾L4重试**：人工确认L4后自动接管，首次超时，以同一幂等键重试成功，新证据触发重新研判。

- 摄像机、道路、隧道、桥梁及边坡基础数据。
- 五个案例所需的合法、脱敏视频或图片素材。
- 视频播放协议、编码和证据授权方式。
- 集团数据保留、统一认证和机构权限制度。
- 新事件类型的智能管控专属规则。

### 32.2 风险

- 真实接口未定导致字段变化。
- 高频告警加重现有单Store性能和维护风险。
- localStorage迁移可能影响现有运行快照。
- 新事件类型进入管控后缺少专业推理规则。
- 生产视频授权、并发锁、权限和审计不能由纯前端完整实现。
- 专业设施异常依赖外部系统，不能由本项目承诺识别准确性。

### 32.3 待决事项

- 数据保留期限的最终制度值。
- 真实AI、设施和第三方接口协议。
- 生产消息通知渠道。
- 统一认证及跨机构协同规则。
- Word版产品方案条款的最终逐段复核。

上述待决事项不阻塞前端MVP，必须通过接口契约、配置项或 `[待确认]` 标记隔离，禁止硬编码为生产事实。

## 33. 本期不实现内容

- 真实生产视频AI、视频流和专业平台接入。
- 真实统一身份认证、服务端数据库和对象存储。
- 桥梁、边坡和隧道传感器波形及结构安全诊断。
- 自动执行交通控制措施。
- 法定事故等级自动认定。
- 手机端完整核实操作。
- 以模拟数据宣称真实算法准确率。
- 未经人工复核由单一AI告警直接创建L4管控事件。
