# 因果顺成推演结论 Skill

## 1. Skill 定位

本 Skill 用于让大模型解释“事理图谱推理链”的业务含义，并输出面向值班员、领导或非专业评审人员可理解的推理结论声明。

它只回答一个问题：

> 当前事件为什么会沿着这条事理链条推到这个处置判断？

本 Skill 不负责解释交通流公式，不负责综合瓶颈通行能力、行驶密度、排队密度、回溯速度等计算指标。上述内容由“交通流计算过程与结论解读 Skill”负责。

## 2. 适用界面位置

- 事理图谱详情弹窗顶部的“因果顺成推演”结论区。
- 推理路径自动播放时，每个高亮节点对应的解释气泡或说明区。
- 图谱推理完成后的一句话结论声明。

## 3. 输入数据契约

调用本 Skill 时，应传入当前事件和当前推理链，不传入其他事件的完整计算过程。

```json
{
  "event": {
    "id": "EV-R006",
    "road": "G65",
    "accidentKp": 1179,
    "label": "G65 K1179 追尾事故",
    "lanesTotal": 3,
    "lanesClosed": 3,
    "q": 3823,
    "severity": "较大"
  },
  "currentStep": {
    "id": "T-6",
    "phase": "推演",
    "title": "因果顺成推演：预测后方拥堵，队尾以 w=9.9 km/h 向上游回溯",
    "conclusion": "瓶颈通行能力归零，后方形成排队并持续回溯。"
  },
  "tracePath": [
    {
      "nodeId": "N_车道占用",
      "nodeLabel": "车道占用",
      "role": "起因"
    },
    {
      "nodeId": "N_后方拥堵",
      "nodeLabel": "后方拥堵",
      "role": "推导"
    }
  ],
  "edges": [
    {
      "from": "N_车道占用",
      "to": "N_后方拥堵",
      "type": "因果",
      "rule": "车道占用导致断面通行能力下降，流量需求无法释放时形成排队。"
    }
  ],
  "ruleFacts": [
    "事故占用全部车道",
    "断面流量仍持续进入事故上游",
    "系统已识别后方拥堵节点"
  ],
  "allowedStepIds": ["T-6"],
  "allowedNodeIds": ["N_车道占用", "N_后方拥堵"]
}
```

## 4. 输出格式

大模型必须只输出 JSON，不输出 Markdown，不输出额外解释。

```json
{
  "title": "因果顺成推演结论",
  "chainExplanation": "本次推理从车道占用开始，判断事故点通行能力下降，进而推导出后方车辆无法及时通过并形成拥堵。",
  "nodeStatements": [
    {
      "nodeId": "N_车道占用",
      "nodeLabel": "车道占用",
      "plainLanguage": "事故占用了可通行车道，这是后续拥堵判断的直接起点。",
      "roleInChain": "起因"
    }
  ],
  "conclusionStatement": "因此，本次图谱推理结论是：事故占道已经触发后方拥堵链条，需要把关注点从事故点扩展到上游队尾变化。",
  "confidence": "中",
  "operatorFocus": [
    "继续观察上游队尾是否接近枢纽或隧道入口",
    "复核现场是否具备临时放行条件"
  ],
  "evidenceRefs": [
    {
      "type": "node",
      "id": "N_车道占用",
      "label": "车道占用"
    }
  ],
  "limits": "该结论解释的是图谱因果链，不替代交通流计算指标结论。"
}
```

## 5. 字段要求

- `title` 固定为“因果顺成推演结论”。
- `chainExplanation` 用 1 至 2 句话解释整条推理链。
- `nodeStatements` 必须按 `tracePath` 顺序输出，不能跳步。
- `nodeId` 必须来自 `allowedNodeIds`。
- `conclusionStatement` 必须声明“图谱推理结论”，不能写成交通流计算结论。
- `operatorFocus` 最多 3 条，必须可操作、可复核。
- `limits` 必须提醒“该结论不是交通流指标综合结论”。

## 6. 禁止事项

- 禁止编造输入中不存在的事件、桩号、节点、资源、人员、电话、车牌。
- 禁止把公式结果当成本 Skill 的主体内容。
- 禁止输出“瓶颈通行能力、行驶密度、排队密度、回溯速度”的综合判定，这些归交通流计算 Skill。
- 禁止直接复述节点名称列表，必须说明节点之间为什么能顺成推导。
- 禁止给出未由图谱链条支持的调度命令。

## 7. 系统提示词建议

```text
你是路网事理图谱推理解释助手。你的任务是解释当前事件为什么会沿着输入中的事理链条推导到当前图谱结论。你只能使用输入中的 event、currentStep、tracePath、edges、ruleFacts，不得新增事实。你不解释交通流公式，不输出交通流指标综合判断。只输出合法 JSON。
```

## 8. 质量校验规则

调用方收到大模型输出后，应执行以下校验：

1. JSON 可解析。
2. `nodeStatements[].nodeId` 全部来自 `allowedNodeIds`。
3. 不出现输入外的事件 ID、桩号、资源 ID。
4. `conclusionStatement` 包含“图谱推理”或“事理图谱”语义。
5. 不出现以交通流指标为主体的综合结论。
6. 若校验失败，回退为规则模板：

```text
因果顺成推演结论：系统已沿当前高亮节点完成图谱推理，本步结论为【{currentStep.conclusion}】。该结论来自事理图谱链路，不替代右侧交通流计算指标判断。
```
