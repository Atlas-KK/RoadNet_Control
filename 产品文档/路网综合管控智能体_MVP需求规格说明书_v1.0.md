## 1. MVP 定位与升级主线

### 1.1 定位

demo 阶段交付的是**功能演示器**：S0–S5 六个脚本化场景证明产品方案的推理逻辑真实可运行。MVP 阶段交付**最小可用产品（单机版）**：同一套推理能力脱离脚本，能够对**任意输入事件**（手工录入或模拟事件源）完成「接入 → 归并 → 推理 → 预案 → 复核 → 下发 → 留痕 → 数据集沉淀」的完整闭环，可用于业主环境的桌面部署试用与图就绪数据采集练兵。

对应产品方案六「落地实施建议」的 v1 阶段（规则 + 检索 + LLM 编排的单事件方案生成，数据按图就绪规范采集），并把 demo 已验证的 v2 图谱推理结构（附录 A 四种推理结构）作为**引擎内建能力**保留——MVP 不是从 demo 后退到纯规则，而是把"脚本演出"升级为"引擎实办"。

### 1.2 三条升级主线

| 主线 | demo 现状 | MVP 目标 |
|---|---|---|
| ① 推理引擎通用化 | 单事件五步推理（reasoner.ts）真实；归并、跨事件冲突、条件组合、自引用检测由场景脚本手工构造 trace/calc/plan | 四种推理结构全部成为 engine 模块，对任意事件输入实时产出 trace/calc/plan；场景脚本薄化为「事件与环境注入序列」 |
| ② 事件接入真实化 | 事件只能由 S0–S5 脚本注入 | 新增运行模式：手工事件录入 + 可选模拟事件源；归并引擎对真实输入流工作；并发事件 ≥5 起 |
| ③ 处置闭环持久化 | 纯内存，刷新即失；无审计、无数据沉淀 | IndexedDB 持久化 + 只增审计留痕 + 图就绪六段数据集采集与 JSONL 导出 + 可选 LLM 文案通道（带值级溯源校验） |

### 1.3 能力边界（继承产品方案 1.4，不得突破）

1. 不自动执行任何改变驾驶行为的控制措施——控制类一律人工确认后生效；
2. 不替代现场指挥权——全部产出定位为处置建议；
3. 不做责任认定与执法判断；
4. 不在低置信时伪装确定——依据不足显式标注并回退规则结论或转人工。

## 2. 运行形态与技术决策

### 2.1 双运行模式

| 模式 | 说明 | 时钟 |
|---|---|---|
| **演示模式**（保留） | S0–S5 场景脚本回放，用于评审与回归；交互与现状一致（播放/暂停/倍速/步进/重播/暂停点门禁） | 模拟时钟 1x/4x/16x |
| **运行模式**（新增） | 空白世界起步；事件来自手工录入表单或模拟事件源；全部推理产物由引擎实时生成 | 真实时钟（1 秒 = 1 秒），支持 4x/16x 加速仅用于练兵 |

顶部 Timeline 增加模式切换；两种模式共用同一 Zustand store 结构与全部引擎，禁止为运行模式复制第二套状态树。切换模式等价于 `loadScenario`/`loadRuntime` 级别的全量状态重置（持久化数据不受影响）。

### 2.2 技术决策记录（实施前提，不再讨论）

| # | 决策 | 理由 |
|---|---|---|
| D1 | **保持纯前端 SPA，不建后端**；持久化用 IndexedDB（自封装薄层，不引入重型 ORM） | 保住「一键启动.bat」零依赖部署；MVP 目标是单机试用与数据练兵；后端服务化列入 post-MVP |
| D2 | **LLM 为可选通道**：OpenAI 兼容 `/chat/completions` 端点直连（覆盖多数国产模型网关），baseUrl/apiKey/model 由配置面板录入、仅存 localStorage；未配置时模板引擎全功能可用 | 信创模型多提供 OpenAI 兼容接口；演示与离线环境不受 LLM 可用性影响 |
| D3 | **场景脚本薄化，而非删除**：S0–S5 保留原时间轴与暂停点，但 trace/calc/plan 的手工构造逐步替换为引擎调用；替换后必须通过 12.1 数值锚点回归 | 演示模式是「引擎正确性的活体测试」，脚本与引擎产出一致即证明引擎通用 |
| D4 | 技术栈不变：React 19 / TypeScript / Vite / Zustand 5 / Tailwind 4 / MapLibre 5 + Leaflet 1.9 双引擎 / Recharts 3 | 现有代码质量门禁齐备，无重选型理由 |
| D5 | 新增依赖上限：IndexedDB 封装可用 `idb`（≈3KB）；不引入图可视化库、不引入状态库替代品、不引入 UI 组件库 | 防止包体与维护面失控 |

## 5. 功能需求

编号规则：`FR-<模块>-<序号>`；优先级 **P0=MVP 必须 / P1=MVP 应当 / P2=可延后**。未标注者为 P0。

### 模块 A 事件接入与归并

**FR-A1 手工事件录入**
运行模式下提供「事件上报」表单（地图工具区入口 + 快捷键 N）。字段：来源（视频检出/电话报警/雷视/人工巡查）、道路（G65/G56/S204）、桩号（校验在道路演示区间内）、事件类型（追尾/侧翻/抛锚/危化品泄漏疑似）、占用车道数/总车道数、断面流量 q（veh/h，默认按道路给缺省值：G65=4300、G56=3300、S204 不仿真）、伤亡人数、危化品标志、备注。提交即进入标准化管道：字段校验（复用 flowModel 输入校验语义）→ 归并判定（FR-A3）→ 五步推理（模块 B）。表单校验失败给出中文错误并阻止提交。

**FR-A2 模拟事件源（P1）**
运行模式可开启「模拟事件源」：按可配置泊松强度（初值 λ=1 起/10 分钟，上限并发 8 起）在演示路网随机生成事件（类型/位置/车道占用按预置分布），用于并发与归并练兵。生成的事件与手工事件走完全相同管道。

**FR-A3 归并引擎（engine/merge.ts，新建）**
输入：新标准化事件 + 当前活跃事件集合。多维匹配评分（初值，集中常量可调）：

```
空间分 s：同路且桩号差 ≤1km → 1.0；≤3km → 0.6；否则 0
时间分 t：上报时差 ≤5min → 1.0；≤15min → 0.5；否则 0
类型分 c：类型相同 → 1.0；相容（追尾↔事故类电话报警）→ 0.7；不容 → 0
方向分 d：同向 → 1.0；方向未知 → 0.8；反向 → 0
总分 = 0.35s + 0.25t + 0.25c + 0.15d
```

处置三档（产品方案 2.6）：总分 ≥0.75 高置信自动归并（新报作为补充字段并入既有事件，产出归并 TraceStep 含得分明细）；0.45–0.75 中置信「并案标记」——预案合并生成、两事件独立跟踪，任一关键字段（伤亡数/车辆数/位置漂移 >1km/危化品标志）冲突即自动拆分并转人工；<0.45 不归并，各自出预案并推送人工比对卡。**硬规则**：同归并组关键字段冲突一律强制拆分。归并/拆分全量写审计流（FR-H1）。S0 的双源归并改经本引擎执行，回归锚点：S0 仍为高置信自动归并且 Trace 显示得分明细。

**FR-A4 归并人工比对卡（P1）**
低置信对给出并排比对卡（两事件字段对照 + 得分），值班员可手工「合并/保持独立」，操作与理由留痕。

### 模块 B 推理引擎通用化

**FR-B1 五步推理统一入口**
`engine/reasoner.ts` 扩展为对任意标准化事件执行完整五步（现状①②③⑤已通用，④推演需接入 B2–B5 的结构化能力）。每步 TraceStep 的 dataSources/edges/calcs/mapRefs/specRef 契约不变（demo-spec 5.2），三端联动保持。

**FR-B2 跨事件冲突校验（engine/conflictCheck.ts，新建）**
实现 demo-spec 5.4 算法为纯函数：输入候选分流路径（路段集合）+ 活跃事件锚点索引 + flowModel；输出「通过/裁剪+备选/无可用分流」与 TraceStep/CalcRecord 序列。活跃实例锚点索引实现为 `Map<road:kpBucket, eventId[]>`（1km 桶）。**任何事件**的预置分流措施生成前都必须经过本校验（不再限于 S1 脚本）。S1 回归锚点：w(B)=7.55、T_conflict=24min、T_arrive=18min、裁剪→提前分流。

**FR-B3 条件求值器（engine/conditions.ts，新建）**
由事件属性 + 环境状态 + 模拟/真实时钟求值条件节点集合：危化品（事件属性）、隧道路段（桩号落在青云隧道 K1176.0–1178.4，GIS 现算）、团雾（雾区活跃且事件位于雾区或其上游 5km 内）、夜间（时钟 22:00–06:00）、设备离线（设备状态）。激活集合驱动：目标边加权（团雾 ×2.2）、措施约束挂载（雾区内禁设封道执行点）、GraphPanel 琥珀点亮。运行模式提供「环境条件」控制（雾区开关与范围、设备离线切换）。封道点参数模板（三候选取 min、就近落雾区外设备）从 S3 脚本迁入 `data/measureTemplates.ts` 通用逻辑。S3 回归锚点：封道点 K1169.5→VMS-05@K1168、VMS-03 裁剪、对照步骤存在。

**FR-B4 资源链推理（engine/resourceChain.ts，从 store 抽出）**
现 store.spawnEvent 内的「占用方事件 → 剩余作业时延 → 转场 → ETA 对比」逻辑抽为纯函数：输入资源占用表 + 事件集合 + 目标事件；输出各候选资源 ETA、推荐策略（等待释放/跨辖区调派）与 CalcRecord。store 与 PlanPanel 消费同一函数。S2 回归锚点：W-01 等待路线 41min < W-EX 48min。

**FR-B5 变长遍历与自引用检测（engine/traversal.ts，新建）**
沿缓存拓扑向上游遍历枢纽（最大深度 2）：每枢纽用 flowModel 算排队到达时间；命中「当前有效预案的分流承接线经过该枢纽下游交叉线」→ 自引用冲突 → 产出方案重构建议（含行动窗口）。对任意含分流措施的活跃预案周期性（模拟时钟每 60s）复检。S5 回归锚点：w=9.8、T(枢纽)=35.5min、17:06 预测兑现。

**FR-B6 人工续报与订正续报**
事件处置期间，值班员可手工提交“续报”或“订正续报”，补充事件动态、现场处置、交通影响和文字描述；初报、续报、终报均属于监控员向上报送的事件信息，不得作为系统管控预案的名称。续报仅补充描述时只写入事件报告与审计流；伤亡、危化品、占道数、交通量、处置进展等影响研判的事实变化时，系统重新研判并生成 `Vn 管控预案`。属性撤回仍走 `engine/tms.ts` 产出逐条保留/降级/撤销清单，作为订正续报的一种特殊情形。历史报告不可覆盖，后续订正以新报告关联原事件留痕。

**FR-B7 消散与处置闭环（P1）**
清障完成（资源到场后按类型作业时延推进，清障 median=45min）触发消散计算 w_d=2w，排队长度回落至 0 后提示「可处置闭环」；处置闭环归档事件（实例摘除动画保留）并生成“事件处置闭环摘要”、触发复盘表单（FR-I2）。该摘要不等同于监控员上报的终报。

### 模块 C 交通流模型

**FR-C1** 公式与参数不变（demo-spec §4）。新增：多事件同路段叠加时，下游事件的 q 输入按上游事件瓶颈流出能力截断（`q_下游 = min(q, C_b_上游)`，产出 CalcRecord 标注来源）。**P1**。

### 模块 D 预案生成与 LLM 通道

**FR-D1 模板引擎为默认与兜底**
现状模板文案保持；底部标注语在 LLM 启用时切换为「本方案文案由 LLM 生成，关键字段经值级溯源校验」。

**FR-D2 LLM 配置与调用**
配置面板（FR-K1）录入 baseUrl/apiKey/model/超时（初值 10s）。启用后，预案生成第 ⑤ 步末尾追加一次 LLM 调用（**每版本预案 ≤1 轮**）：输入为结构化研判包（事件快照摘要 + 措施清单 + 计算结论），要求输出预定义 JSON schema（方案摘要 ≤120 字、各措施说明 ≤40 字、风险提示 ≤60 字）。

**FR-D3 schema 校验与值级溯源比对**
LLM 输出先过 JSON schema 校验（字段/类型/长度）；再做值级比对：文案中出现的桩号、资源 ID、ETA 分钟数、电话必须与引擎产物**逐字段一致**（正则抽取 + 白名单比对），任一不一致 → 拒绝该输出、回退模板文案、比对差异写审计流。规则优先仲裁：LLM 表述与措施清单冲突时以引擎清单为准。

**FR-D4 LLM 失败降级**
超时/网络错误/校验拒绝均静默回退模板并在预案卡标注「LLM 通道不可用，已回退模板」；全部 prompt/response/拒绝原因入审计流。演示模式**永不调用 LLM**。

### 模块 E 复核与下发

**FR-E1** 三档复核、待办排序、强制升级打断保持现状。

**FR-E2 确认时效（运行模式）**
控制类待办显示真实倒计时（目标 ≤3min，产品方案 2.7）；超时 → 待办条目升级样式 + 顶部横幅「已超时，升级通知值班长」（单机版以界面提示模拟逐级通知）；持续超时（≥6min）执行**最小安全动作集**：仅自动执行实况类发布与「联动提醒已记录」条目，控制类维持待确认，全过程写审计流。演示模式不启用倒计时（演示时长不可控，沿用标签展示）。

**FR-E3 打回**
待办确认按钮旁增加「打回」：必填理由，措施回到草案并通知（界面提示）重新研判；打回记录入审计流与数据集 feedback 段。

### 模块 F 版本状态机

**FR-F1** 现状规则保持（替换自动、历史只读、三键确认）。
**FR-F2 作废与证伪（人工触发）**
预案卡提供「作废」（必填理由：现场接管/方案有误/其他）；事件卡提供「事件证伪」（感知误报）——证伪则最新版本作废、事件标记误报并归档，误报样本进数据集 label 段。作废不可自动触发（产品方案 2.7 权责语义）。

### 模块 G GIS 与全网态势

**FR-G1 并发承载**
地图与拥堵网格支持 ≥5 起并发活跃事件渲染（拥堵网格现限 2 行，改为可纵向滚动列表）；事件图层/队尾/资源移动逻辑不变（共享 twinMapModel）。

**FR-G2 全网事件列表**
地图面板增加折叠式「活跃事件列表」（事件 ID/道路桩号/等级/当前演化阶段/待办数），点击定位地图并联动监控与预案面板。

**FR-G3 地图快捷操作（P1）**
运行模式下右键（或长按）路网 → 「在此上报事件」预填道路与桩号。

**FR-G4 角色视图（P2）**
按交管/养护/医疗裁剪的只读分发视图。MVP 仅保留界面占位说明，不实现。

### 模块 H 持久化与审计

**FR-H1 审计流（只增不改）**
IndexedDB 库 `roadgov-mvp`，object store `audit`：每条 `{ seq 自增, tsReal, tsSim, kind, eventId?, planId?, version?, payload }`。写入点：事件接入/归并/拆分、人工续报/订正续报、TraceStep 批次、管控预案版本生成与状态流转、确认/打回/作废/证伪、超时升级、LLM 调用与校验结果、数据集导出。UI 提供只读「审计」抽屉（按事件过滤，倒序）。演示模式不写审计库（回放不产生真实责任记录）。

**FR-H2 运行态持久化**
运行模式的事件、预案、资源占用、数据集草稿写 IndexedDB，刷新后可恢复「继续处置」；提供「清空运行库」（二次确认 + 导出提醒）。

**FR-H3 推理快照存档**
每次五步推理的快照对象（含快照时间与范围）随审计流存档，预案卡可展开「基于 HH:MM:SS 快照生成」并查看快照内容（产品方案 3.3.4「事后复现当时系统看到的世界」）。

### 模块 I 图就绪数据集

**FR-I1 六段结构采集**
按产品方案 4.1/4.4 六段结构定义 TypeScript 类型并在处置全程自动填充：

```ts
interface DatasetRecord {
  event: { id; type; road; kp; lanes; casualties; hazmat; sourceKind; tsDetect };
  context: { snapshotTs; weather: string[]; devicesOffline: string[]; flowQ; concurrentEventIds: string[] };
  event_logic: { chain: { from; to; relation: '因果'|'顺承'|'条件'; confirmed: boolean }[] }; // 复盘表单确认
  plan: { versions: { version; label; measures: { measureId; tier; runState; diff? }[] }[] };
  label: { outcome: '正常处置'|'误报'|'归并拆分'|'作废'; confirmTimeSecList: number[] };
  feedback: { rejects: { measureId; reason }[]; revokeNotes: string[] };
}
```

**FR-I2 复盘表单**
事件处置闭环后弹出结构化复盘表单：系统预填候选演化链（本次推理实际走过的事理边）供勾选/修正（对应 4.4「预填候选演化链」），补全 event_logic 后记录落库。可「稍后填写」，未完成项在数据集导出时标注 `event_logic.confirmed=false`。

**FR-I3 JSONL 导出**
「数据集导出」生成 JSONL 文件下载（一行一事件）；同时支持审计流 JSON 导出。导出动作本身写审计流。

### 模块 J 时钟与模式

**FR-J1** 演示模式时钟行为不变。运行模式默认真实时钟（1s=1s），可切 4x/16x 练兵档；切换模式必须全量重置内存态（复用 freshScenarioState 模式）。运行模式下 pause 语义为「冻结推演」，事件录入仍可用。

### 模块 K 系统配置

**FR-K1 配置面板**
右上角齿轮入口：LLM 配置（D2）、模拟事件源开关与强度（A2）、归并阈值三档（A3，显示初值与当前值）、环境条件控制（B3）、清空运行库（H2）。配置存 localStorage，带「恢复默认」。
