## 1. Demo 定位与边界

### 1.1 定位

本 demo 是**功能演示器（Demonstrator）**，不是生产原型。它的唯一使命：向评审专家与业主直观证明产品方案 v1.7 的核心推理能力是真实可运行的逻辑，而非 PPT 概念。因此：

- **推理过程必须全程透明**：每一步推理显示走过的图谱边、数据来源、中间结论；
- **计算过程必须全程透明**：每一个数值结论（蔓延时点、封道桩号、等待收益）显示公式、代入值、计算结果；
- **可视化必须与推理同步**：图上高亮的路径、路网上的拥堵动画，与推理轨迹面板逐条对应。

### 1.2 边界（明确不做）

| 不做 | 替代方式 |
|---|---|
| 真实 LLM 调用 | 预案文案由模板引擎渲染；每个关键字段可 hover 查看「来源指针」，模拟 3.5 值级溯源 |
| 真实图数据库/GIS/关系库/时序库 | 全部为内存 TypeScript 对象（对应方案的逻辑角色，见 3.6 角色映射） |
| 后端服务、持久化、登录权限 | 纯前端 SPA，刷新即重置 |

| 移动端适配 | 仅桌面 Chrome，目标分辨率 1920×1080 |

节点五类与边两组严格按方案 3.3.1。demo 初始图谱规模控制在 **25±5 个类型节点、35±5 条边**，完整列出关键子集（Claude Code 需实现全部下列节点边，可少量补充无害节点）：

**事件类型节点**：追尾事故、货车侧翻、车辆抛锚、危化品泄漏（疑似/确认两态由实例属性表达）、车道占用、后方拥堵、二次事故风险、伤亡。

**措施节点**（关联 3.5 参数模板）：上游限速、封闭车道、全幅封道、预置分流、提前分流、调派清障、调派120、调派消防、隧道通风控制、情报板实况发布、拥堵预警发布、临时交通组织（匝道管制提示）。

**资源类型节点**：清障车、救护车、消防力量、路政班组、情报板。

**约束/条件节点**：隧道路段、团雾、夜间、危化品、无可用匝道、设备离线、雾区内禁设封道执行点。

**事理边（示例，全部带属性）**：

```
追尾事故 —因果→ 车道占用
货车侧翻 —因果→ 车道占用
车辆抛锚 —因果→ 车道占用
车道占用 —顺承(w=0.82, Δt~LogN(median=12min))→ 后方拥堵
后方拥堵 —顺承(w=0.31)→ 二次事故风险
团雾 —条件·加权(×2.2)→ [后方拥堵→二次事故风险]
危化品∧隧道 —条件·激活→ 有毒气体聚集风险
清障作业 —顺承(Δt~median=45min, p80=68min)→ 清障完成   ← 场景S2的核心时延边
```

**知识边（示例）**：

```
伤亡 —触发→ 调派120
危化品泄漏(疑似) —触发→ 调派消防 / 全幅封道
车道占用 —触发→ 封闭车道 / 调派清障 / 情报板实况发布
后方拥堵(预测) —触发→ 拥堵预警发布 / 预置分流 / 上游限速
调派120 —需要→ 救护车
调派清障 —需要→ 清障车
封闭车道 —适用于→ 隧道路段(参数模板切换为隧道版)
全幅封道 —受约束→ 雾区内禁设封道执行点
```

### 3.5 措施参数模板（measureTemplates.ts）

每个措施节点挂参数模板函数，输入为事件上下文，输出为带溯源的参数。核心模板：

| 措施 | 参数模板逻辑 |
|---|---|
| 封闭车道 | 封闭数=占用车道数；隧道内附加「保留车道限速 40 km/h + 引导」 |
| 全幅封道 | 封道执行点 kp = min(事故点上游安全距离点, 隧道入口−0.5 km, 雾区上游边界−0.5 km)，再就近落到**雾区外**的可执行情报板/收费站 |
| 隧道通风控制 | 泄漏物密度轻于空气 ∧ 洞内自然风向=正向 → 正向排风至出口侧；出口侧下游 1.5 km 设无人管制区；人员疏散方向=逆风侧 |
| 预置分流 | 默认路径=经 K1160 枢纽 → G56 K26 汇入；执行前必须通过「跨事件冲突校验」（第 5.4 节） |
| 提前分流 | 路径=K1140 互通 → S204，绕行代价 +12 min |

每个输出参数携带来源指针：`{ value, source: '模板计算'|'GIS现算'|'快照'|'流模型', formulaRef?: calcId }`。

## 4. 简化交通流计算模型（flowModel.ts）

demo 采用**确定性排队/激波简化模型**，只求量级正确与过程可展示，不追求仿真精度。所有计算必须产出 `CalcRecord` 进入计算面板。

### 4.1 公式与默认参数

| 量 | 公式 | 默认参数 |
|---|---|---|
| 瓶颈通行能力 | `C_b = (n − k) × C_lane × α` | C_lane=1800 veh/h/车道，事故干扰折减 α=0.85 |
| 行驶密度 | `k_a = q / v_f` | v_f=110 km/h |
| 排队密度 | `k_q = k_j × n` | k_j=140 veh/km/车道 |
| 排队尾部回溯速度 | `w = (q − C_b) / (k_q − k_a)`（q>C_b 时） | 单位 km/h |
| 排队到达某点时间 | `T(kp) = distance(事故点上游, kp) / w` | 分钟输出 |
| 排队长度 | `L(t) = w × t` | |
| 消散（清障完成后） | 消散速度 `w_d = 2 × w`（演示级简化） | |

### 4.2 展示要求（强制）

计算面板中每条 `CalcRecord` 渲染为三行：**公式（含符号）→ 代入（实际数值）→ 结果（含单位）**，并标注数据来源徽章（如 `q ← 时序流` `n,k ← 事件快照`）。示例渲染：

```
排队回溯速度  w = (q − C_b) / (k_q − k_a)
              = (5200 − 1530) / (420 − 47.3)
              = 9.8 km/h        [q←时序流] [C_b←本面板#2] [k_j,v_f←模型参数]
```

### 4.3 与方案叙述数值的差异声明

附录 A 案例叙述中的部分距离/时间为说明性示例（如案例五「上游 20 公里、35 分钟到达」在本简化模型下不自洽）。**demo 一律以本模型算得数值为准**，场景参数（第 8 节）已按模型反推校准，使演示结论与附录 A 的推理结论一致（冲突成立/等待更优/35 分钟窗口等），仅具体距离数字不同。UI 中不需要展示此差异，本条仅约束开发。

## 5. 推理引擎与推理轨迹（reasoner.ts / trace.ts / tms.ts）

### 5.1 五步推理流程

严格按方案 3.3.7 实现，每步产出一条或多条 `TraceStep`：

① **事件落图**：创建事件实例节点（EV-xxx），挂路段锚点、连接事件类型节点；
② **生成推理快照**：按事件位置圈定上下文（demo 简化为全网络，但 UI 上仍展示「快照范围框」与快照时间戳；场景 S1 演示一次**增量补取**：分流承接路径 G56 段在初始快照范围外，校验分流时补取并单独标注取数时间）；
③ **多跳子图检索**：沿事理边取演化候选，用快照上下文实例化到具体路段；
④ **因果/顺承/条件推演**：按边权与条件激活状态推演，时空定量调用 flowModel；
⑤ **约束裁剪与措施匹配**：沿知识边匹配措施、参数模板填参、可行性裁剪（含跨事件冲突校验），生成措施清单与执行工单引用。

### 5.2 Trace 数据结构（强制接口）

```ts
interface TraceStep {
  id: string;                    // 'T-0031-04'
  eventId: string;
  phase: '落图'|'快照'|'检索'|'推演'|'裁剪匹配'|'撤销传导';
  title: string;                 // 一句话结论，如「预测后方拥堵将于 +24min 覆盖 G56 承接段」
  dataSources: ('图库'|'快照'|'快照·增量补取'|'缓存拓扑'|'流模型'|'规则'|'模板')[];
  edges?: { from: string; to: string; type: string; weight?: number }[]; // 走过的图谱边→GraphPanel 高亮
  calcs?: string[];              // 关联的 CalcRecord id → CalcPanel 联动定位
  mapRefs?: string[];            // 关联的路网元素 id → NetworkMap 联动高亮
  conclusion: string;
  specRef: string;               // 对应方案章节号，如 '3.3.7-④ / 附录A案例一'
}
```

**联动是硬性要求**：点击 TraceStep → GraphPanel 高亮其 edges、CalcPanel 滚动到其 calcs、NetworkMap 高亮其 mapRefs。这是「推理透明」的落点。

### 5.3 四种推理结构的实现要点

| 结构 | 实现 | 场景 |
|---|---|---|
| 跨事件实例取数 | 活跃实例锚点索引：`Map<segmentId, eventId[]>`；分流路径路段集合反查活跃实例；资源 `occupiedBy` 跳转占用方事件并读其演化阶段与剩余时延 | S1 / S2 |
| 条件动态组合 | 条件节点按事件上下文求值激活；激活的条件边对目标边加权、向措施挂约束；激活集合在 GraphPanel 中点亮 | S3 |
| 依据反向传导（tms.ts） | 每条已生成措施携带 `supports: factId[]`；事实撤回→遍历所有措施：supports 全失效→撤销；部分失效→按剩余依据重跑参数模板（可能降级）；不受影响→保留。输出逐条清单喂给状态机 | S4 |
| 变长自引用遍历 | 排队回溯沿缓存拓扑逐节点推进（最大深度 2 个枢纽）；每到一个枢纽调用流模型算到达时间；命中「当前预案分流路径包含该枢纽下游交叉线」→ 自引用冲突，触发方案重构 | S5 |

### 5.4 跨事件冲突校验（S1 核心算法）

```
输入：本事件 A 的候选分流路径 P（路段集合，GIS 角色现算）
1. 用锚点索引反查 P 上的活跃事件实例 → 命中 EV-B
2. 读 EV-B 当前演化节点（清障中/拥堵扩展中）
3. flowModel 计算 B 拥堵覆盖 P 关键汇入区的时间 T_conflict
4. 计算 A 分流车流到达汇入区时间 T_arrive（路径距离/建议车速）
5. 若时间窗重叠（T_arrive ≥ T_conflict − 缓冲5min）→ 裁剪 P，取备选路径重新校验
输出：通过的路径 或「无可用分流」结论
```

## 6. 预案、版本状态机与三档复核

### 6.1 版本状态机（stateMachine.ts）

状态集：`草案 → 待确认 → 已确认 → 已下发 → 执行中 → 已完成 / 已作废 / 已被替换`。规则严格按方案 2.7：新版本生成时待确认旧版自动转「已被替换」；已确认/已下发旧版措施在新版中逐条标注 `继承 / 新增 / 撤销`（撤销生成回收指令措施）；差异高亮。UI 上每个预案卡片带 StateMachineMini 迷你状态图，当前状态点亮，流转时有 300ms 过渡动画。

### 6.2 三档复核（review.ts）

| 档 | 判定 | demo 行为 |
|---|---|---|
| 控制类 | 限速/封道/分流/调派/实质引导驾驶行为的文案 | 进待办队列，需点击「确认下发」；确认后计时展示「确认耗时」 |
| 实况发布类 | 已确认事件的客观提示 | 自动执行，队列中灰色留痕条目标注「自动+审计」 |
| 预测预警发布类 | 基于预测的预警 | 进待办队列，按钮为「一键确认」（单击即过，视觉上更轻） |

待办队列按风险优先级排序；场景 S3 演示一次「强制升级打断」：危化品事件确认项以全屏模态弹出。确认超时兜底不做倒计时联动（演示时长不可控），仅在队列条目上显示「目标 ≤3min」标签。

### 6.3 预案文案模板

预案渲染为结构化卡片：责任主体 / 措施清单（含三档标记、参数、来源指针 hover）/ 资源与 ETA / 依据链接（点击跳 Trace）/ 置信标注。文案模板底部固定标注：「演示环境：文案由模板引擎生成，生产环境由 LLM 生成并经值级溯源校验（方案 3.5）」。

### 7.2 NetworkMap 规格

- 手写 SVG：G65 水平主带（车道细分线），G56 斜向交叉于枢纽，S204 细线；隧道段深色框+图例；桩号刻度每 10 km 一档，关键点位标签；

- **拥堵可视化**：从事故点向上游延伸的红-橙渐变色带，长度 = flowModel 的 L(t)，随模拟时钟逐帧增长；排队尾部标注当前桩号；
- 分流路径：绿色虚线流动动画；被裁剪的路径：红色叉标 + 变灰；
- 快照范围框：浅蓝半透明矩形；增量补取区域：追加的浅蓝框 + 「补取 @HH:MM:SS」标签；
- 场景 S3 附加：雾区灰色半透明带（K1170–K1174）、隧道风向箭头、无人管制区斜纹带。

### 7.3 GraphPanel 规格

- 双区布局：上区类型层（静态力导或手排坐标，**建议手排固定坐标**保证演示稳定），下区实例层（事件实例动态挂载/摘除动画）；
- 边按类型区分线型：因果实线、顺承实线+时延标签、条件虚线、知识边（触发/适用/需要）细实线；
- 推理路径高亮：TraceStep 联动时相关边加粗发光并按推理顺序做流光动画（200ms/边）；
- 条件节点激活：琥珀色填充点亮；依据撤回（S4）：被撤事实节点变灰划叉，传导动画沿依据边反向逐条推进，措施节点按结论变色（保留=青/降级=琥珀/撤销=珊瑚）。

### 7.4 CalcPanel / TracePanel / PlanPanel 交互细节

- CalcPanel 支持按事件过滤；每条 CalcRecord 可展开「参数来源」子表；
- TracePanel 步骤按 phase 分组折叠，specRef 显示为角标（如 `附录A·案例一`）——这是演示时向评审证明「demo 与方案逐条对应」的关键元素；
- PlanPanel 版本 Tab 显示 V1/V2/V3…，切换时措施 diff 以「继承（灰）/新增（青底）/撤销（珊瑚底删除线）」渲染；
- recharts 图表内嵌于 CalcPanel：场景 S2 的双时间线对比图（等待路线 vs 跨辖区路线的到位时间甘特/阶梯图 + B 排队过匝道时刻竖线）、场景 S5 的排队距离-时间曲线（横轴模拟时间、纵轴排队尾桩号，标注枢纽桩号水平线与交点）。

## 11. 明确不实现清单（防scope蔓延）
