## 1. R1【TracePanel】修复过滤按钮语义（必须先做）

**文件**：`src/components/TracePanel.tsx`

**缺陷事实**（已实测复现）：`showAll` 默认 `false`（过滤生效），此时按钮文案为 `只看 EV-R003`——描述的是**当前状态**，但用户按**动作**理解，点击后 `showAll` 变 `true` → 反而显示全部事件。且 `showAll` 不随聚焦切换重置，一旦翻转会持续污染后续所有聚焦。

**要求**：

1. 按钮文案改为**动作语义**（点它会发生什么），并且**必须**同时显示当前状态，二者不得混淆。采用双段开关（segmented control），**不要用单个 toggle 按钮**：
   - 容器 `data-testid="trace-filter-toggle"`（沿用原 id，勿改）。
   - 两个段：左段文案固定为 `只看当前`，右段文案固定为 `全部事件`。
   - 当前生效的那一段高亮（背景 `var(--color-brand)`、文字白色）；另一段为普通文字色，可点击。
   - 点左段 → `setShowAll(false)`；点右段 → `setShowAll(true)`。点已高亮的段为无操作。
   - 左段文案**不得**内插 `focusedEventId`（避免再次产生"这是状态还是动作"的歧义）；当前聚焦事件号已由步骤卡上的事件徽章表达。
2. **`showAll` 必须随聚焦切换重置为 `false`**：
   ```ts
   useEffect(() => { setShowAll(false); }, [focusedEventId]);
   ```
   放在 `showAll` 声明之后。
3. 门控不变：仅 `mode === 'runtime' && focusedEventId` 时渲染该开关；演示模式不渲染、不过滤。
4. 过滤逻辑（第 90–92 行）本身**正确，不要动**。

## 2. R2【新组件】预案与推理轨迹合并为单窗口（Tab）

**新建**：`src/components/PlanTracePanel.tsx`
**修改**：`src/App.tsx`

**设计判据（供理解，勿偏离）**：预案回答「方案是什么」、轨迹回答「凭什么」，二者是一体两面（预案措施卡的「依据 T-xxx」直指轨迹步骤）。合并后该列宽度约 517px，**必须用 Tab 切换，不得上下堆叠**——堆叠会让两者各只剩 ~440px 高，双双不可用；Tab 下各自可占满 ~880px 通高。

**要求**：

1. `PlanTracePanel` 结构：
   - 用 `usePanelFullscreen('plan-trace-panel', '预案与推理轨迹')` + `PanelFrame`（`testId="plan-trace-panel"`）。
   - `customHeader`：左侧标题 `▤ 预案与推理轨迹`；中部为 Tab 组 `data-testid="plan-trace-tabs"`，两段：`预案`（`data-testid="tab-plan"`）、`推理轨迹`（`data-testid="tab-trace"`）；右侧放 `fullscreen.button`。
   - Tab 状态：`const [tab, setTab] = useState<'plan'|'trace'>('plan')`，**默认 `plan`**（预案是可执行对象，优先级高于依据）。
   - `推理轨迹` Tab 文案右侧带计数徽章：当前可见步骤数（运行模式且有聚焦时为聚焦事件步骤数，否则为全部步骤数）。
   - 主体：`tab === 'plan'` 渲染 `<PlanPanel embedded />`；`tab === 'trace'` 渲染 `<ReasoningPanel embedded />`。**两者都必须挂载**（用 CSS `hidden` 隐藏非当前 Tab，不要卸载），以保留各自的滚动位置与内部状态（版本 Tab、折叠态、详情弹窗）。
2. `PlanPanel.tsx` 与 `ReasoningPanel.tsx` 各新增可选 prop `embedded?: boolean`：
   - `embedded === true` 时：**不渲染自身的 `PanelFrame` 外壳与全屏按钮**，只渲染主体内容（外层用 `<div className="h-full min-h-0 flex flex-col">` 包裹）。
   - `embedded` 缺省/false 时：**行为与现状完全一致**（演示模式走这条路径）。
   - `PlanPanel` 的版本 Tab（V1/V2）在 embedded 下仍需渲染，移入其主体内容顶部一行。
3. `App.tsx`：
   - 演示模式：继续渲染现有的 `<ReasoningPanel />` 与 `<PlanPanel />` 下层双列，**一行不改**。
   - 运行模式：不再渲染下层双列，改用 `<PlanTracePanel />`（位置见 R3）。

## 4. R4【监控抽屉】现场监控改按需触发

**新建**：`src/components/MonitorDrawer.tsx`
**修改**：`src/App.tsx`、`src/components/EventTriageList.tsx`

**要求**：

1. 开关状态提升到 `App.tsx` 本地状态：`const [monitorOpen, setMonitorOpen] = useState(false)`（**不要**放进 store）。
2. `MonitorDrawer` 只在 `mode === 'runtime' && monitorOpen` 时渲染，定位在 R3 那个 `relative` 行内：
   ```tsx
   <div className="absolute inset-y-0 right-0 z-[150] w-[560px] max-w-[70%] shadow-[0_0_60px_rgb(0_0_0/0.55)]"
        data-testid="monitor-drawer">
     {/* 内部复用 <MonitorPanel selectedCameraId={...} /> */}
   </div>
   ```
   - `absolute inset-y-0` 使抽屉**上下边界与该行（即 GIS 窗口）严格对齐**——这是需求「高度与轻量 GIS 窗口对齐」的实现方式，不要用 `fixed` 或自算高度。
   - 抽屉覆盖「预案轨迹 + 待办」两列；**不加全屏遮罩**（指挥员需继续看左侧分诊与态势图）。
   - 抽屉右上角关闭按钮 `data-testid="monitor-drawer-close"`；按 `Esc` 亦关闭（在 `MonitorDrawer` 内挂 `keydown` 监听，卸载时移除）。
3. **触发点（三处，全部调用 `setMonitorOpen(true)`）**：
   - ① 地图摄像机点选：现有 `onCameraSelect` 回调内，除 `setSelectedCameraId(id)` 外追加打开抽屉。
   - ② `EventTriageList` 每行新增一个摄像机图标按钮 `data-testid="triage-cam-{eventId}"`（放在现有 `✕`/`⚠` 左侧）：点击 → `focusEvent(eventId)` + 打开抽屉。为此 `EventTriageList` 新增可选 prop `onOpenMonitor?: (eventId: string) => void`，由 `App` 注入。
   - ③ 保留 R3 前既有的「聚焦变化自动跟随最近摄像机」逻辑（第一轮 T7）：**只更新 `selectedCameraId`，不得自动弹开抽屉**（避免每次切聚焦都弹窗打扰）。
4. `MonitorPanel.tsx` 本身**不得修改**。
