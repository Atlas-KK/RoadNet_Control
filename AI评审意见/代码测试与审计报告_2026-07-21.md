## 4. 本轮发现项

### [P3] 缺少浏览器端 E2E/视觉回归测试

影响：

当前核心逻辑测试覆盖较好，但 UI 主要依赖单元测试、构建检查和人工查看。最近已按 Ant Design Community 风格调整界面，缺少自动化截图或浏览器流程测试来持续保障布局、地图加载、抽屉、弹窗、全屏、事件上报等真实交互。

建议：

- 引入 Playwright 或 Cypress。
- 至少覆盖：
  - 打开首页无白屏。
  - 上报事件后左侧队列出现事件。
  - 点击事件后地图与处置时序联动。
  - GIS 兼容模式/诊断按钮可用。
  - 监控抽屉可打开关闭。
  - 配置弹窗、审计抽屉、导出按钮不报错。
  - 关键视口宽度下文本不溢出。

### [P3] `mapOverlays.ts` 中 T7 地图叠加要素仍未实现

影响：

`wind/controlZone/closure` 三类要素当前仍不生成。如果演示或文档声称地图已经完整展示通风方向、无人管制区、封道执行点，会形成产品口径与实现状态不一致。

建议：

- 短期：在 README、演示说明或验收清单中标注为后续版本能力。
- 中期：从当前聚焦事件的预案措施参数读取封道点、通风方向、管制区范围，回填到 `resolveMapOverlays`。
- 补充对应测试，避免再次写死单一样例场景。

### [P3] LLM 成功调用链路缺少 mock fetch 测试

影响：

当前 `llm.test.ts` 对 schema、值级溯源、endpoint 白名单、无 API Key 行为覆盖较好，但 `generatePlanNarrative` 的成功 HTTP 调用、HTTP 非 2xx、超时 abort、返回非法 JSON 等分支仍主要依赖代码阅读判断。

建议：

- 使用 Vitest mock `globalThis.fetch`。
- 覆盖：
  - 成功返回合法 JSON。
  - HTTP 500 返回 `unavailable`。
  - 非法 JSON 返回 `rejected`。
  - 超时 abort 返回 `unavailable`。
  - LLM 返回伪造桩号/资源/ETA 时被拒绝。

### [P3] 依赖审计依赖官方 registry，默认镜像源无法完成安全审计

影响：

本机默认 `npmmirror` 不支持 npm audit 安全接口，直接执行 `npm audit` 会失败。虽然本轮已用官方 registry 完成审计且结果为 0 漏洞，但如果后续评审脚本继续使用默认源，会产生误报式失败。

建议：

- 在项目 README 或 CI 脚本中明确依赖审计命令使用官方 registry：
  - `npm audit --audit-level=moderate --registry=https://registry.npmjs.org`
- 或在 CI 环境单独配置支持 audit 的安全扫描器。

## 5. 安全审计摘要

已检查风险点：

- HTML 注入：未发现 `dangerouslySetInnerHTML`、`setHTML`、`innerHTML` 业务拼接点；事故弹窗使用 text node。
- 动态执行：未发现 `eval`、`new Function`、`document.write`。
- 浏览器存储：运行快照使用 localStorage，带结构守卫；LLM Key 使用 sessionStorage。
- 网络调用：LLM 调用仅在配置 API Key 后触发，endpoint 限制 HTTPS 或本地地址。
- 文件导出：导出使用 `Blob` + `URL.createObjectURL`，导出数据不含 LLM API Key。
- 定时器：`setInterval` / `setTimeout` 均有对应清理逻辑，地图加载 watchdog 和队列刷新未发现明显泄漏。

安全结论：

当前未发现直接阻断演示或联调的安全问题。建议后续重点补齐 E2E 安全回归与 LLM fetch 分支测试。
