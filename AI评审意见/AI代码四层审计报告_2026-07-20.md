## Findings

- `[P1] 运行模式事件上报表单的数值边界校验不完整，非法车道值会触发核心引擎异常`
  File: `demo/src/components/RuntimeBar.tsx:74`
  Layer: Human review / Test validation
  Impact: 运行模式是事件接入入口，但当前只校验 `lanesTotal` 是否为整数，未校验 `lanesTotal > 0`，也未校验 `lanesClosed` 是否为整数。用户可以输入“总车道=0、占用车道=0”或“占用车道=1.5”，表单层会放行；随后 `computeFlow` 会在核心引擎抛出 `车道参数非法`，导致本次上报失败且界面没有友好错误提示。
  Evidence: `RuntimeBar.tsx:74` 仅判断 `!Number.isInteger(lanesTotal) || lanesClosed < 0 || lanesClosed > lanesTotal`；`RuntimeBar.tsx:83-95` 随后直接构造 `RuntimeEventInput` 并调用 `ingestEvent`；`demo/src/engine/flowModel.ts:53-59` 对非有限值、非整数车道、`n <= 0` 会直接抛错。现有 `ingest.test.ts` 覆盖了正常接入、归并、冲突、危化品和伤亡路径，但没有覆盖运行表单非法输入。
  Modification advice: 抽出 `normalizeRuntimeEventInput` 或 `validateEventEntryForm` 纯函数，统一校验 `lanesTotal` 为正整数、`lanesClosed` 为非负整数且不大于总车道、`q` 为有限非负数、`casualties` 为空或非负整数；`submit` 中在调用 `ingestEvent` 前完成校验，并对 `ingestEvent` 可能抛出的错误兜底显示给用户。补充表单/纯函数测试，覆盖总车道为 0、占用车道小数、伤亡人数非法字符串等场景。

- `[P2] 地图事故弹窗使用未转义 HTML 字符串，后续接入外部事件或损坏快照时存在 XSS 风险`
  File: `demo/src/components/GisNetworkMap.tsx:597`
  Layer: Security
  Impact: MapLibre 弹窗通过 `setHTML` 拼接 `properties.id / label / road / kp`。当前表单大部分字段来自固定选项，但事件对象也可能来自运行快照、模拟数据或后续外部接入。如果事件标签或持久化快照被污染，恶意 HTML 会被当成 DOM 插入。
  Evidence: `GisNetworkMap.tsx:597-600` 使用 `.setHTML(`<div ...>${properties.label}...</div>`)`；事件标签在 `demo/src/engine/ingest.ts:30` 属于 `RuntimeEventInput.label`，并在 `demo/src/engine/ingest.ts:147` 写入事件；运行快照由 `demo/src/services/persistence.ts:113-115` 从 localStorage 恢复，当前仅检查 `version`。
  Modification advice: 不再使用 `setHTML` 拼接业务字段。改用 `setDOMContent` 创建 DOM 节点并通过 `textContent` 赋值，或至少集中使用 HTML escape 函数处理所有动态字段。补充一个安全回归测试或组件级测试，构造包含 `<img onerror=...>` 的事件标签，验证弹窗内容不会被作为 HTML 执行。

- `[P2] 运行快照只校验 version，缺少结构校验，损坏或旧版本 localStorage 数据可能破坏运行态`
  File: `demo/src/services/persistence.ts:113`
  Layer: Human review / Security
  Impact: `loadRuntime` 只判断 `snap.version === 1`，没有验证 `events/plans/trace/environment` 等字段结构。只要 localStorage 中存在 `{version:1}` 但字段缺失或类型错误，`store.setMode('runtime')` 会把坏数据装入 Zustand；随后 `snap.events.filter(...)`、地图渲染、预案面板或推理面板都有机会抛错。
  Evidence: `persistence.ts:81-87` 的 `parse<T>` 直接把 JSON 转成泛型；`persistence.ts:113-115` 只检查 `version`；`demo/src/store.ts:568-585` 恢复快照时直接访问 `snap.events/filter`、`snap.plans`、`snap.trace`、`snap.environment` 等字段。
  Modification advice: 为 `RuntimeSnapshot` 增加运行时类型守卫，例如 `isRuntimeSnapshot(value): value is RuntimeSnapshot`，至少验证 `version`、核心数组字段、`environment.fogBands/offlineDeviceIds`、`simSec/sceneBaseSec` 的类型。校验失败时丢弃快照、保留审计提示或界面提示“运行快照损坏，已重置”。补充 corrupted localStorage 的测试。

- `[P2] LLM API Key 持久化在 localStorage，和可配置 baseUrl 组合后安全边界偏弱`
  File: `demo/src/components/RuntimeBar.tsx:160`
  Layer: Security
  Impact: 配置面板把 `apiKey` 与 `baseUrl/model` 一起保存到 localStorage。localStorage 中的长期密钥容易受到 XSS、浏览器插件、共享电脑和调试导出影响；同时 `baseUrl` 可任意配置，后续一旦 `generatePlanNarrative` 接入实际调用，密钥会被发送到用户填入的任意 OpenAI 兼容端点。虽然这是演示系统，但属于较典型的“本地能用、长期安全边界不清”的 AI 代码风险。
  Evidence: `RuntimeBar.tsx:160-171` 从 `localStorage` 读取并写入完整 `LlmConfig`；`RuntimeBar.tsx:180` 接收 `apiKey`；`demo/src/services/llm.ts:120-122` 调用 `${baseUrl}/chat/completions` 并设置 `Authorization: Bearer ${config.apiKey}`。当前 README 说明“不在组件中硬编码外部接口密钥、生产电话号码或真实调度数据”，但没有说明密钥持久化策略。
  Modification advice: 将 `apiKey` 改为仅内存保存或 `sessionStorage`，并在配置面板明确“仅本次会话使用”；如必须持久化，应单独加确认开关、遮蔽导出、清除按钮和可信端点说明。建议限制 `baseUrl` 协议为 `https` 或本地开发地址，并在发送前提示用户确认端点归属。

- `[P3] `mapOverlays.ts` 中的 T7 TODO 已被测试固化为“不生成”，需要转成明确的产品缺口或阶段性范围说明`
  File: `demo/src/gis/mapOverlays.ts:9`
  Layer: Human review
  Impact: `wind/controlZone/closure` 三类要素当前不生成，代码注释解释了原因，且测试在 `mapOverlays.test.ts:38-42` 固化了“不生成”的行为。这不是立即缺陷，但如果报告、演示或 README 仍声称地图包含“封道点、风机/通风方向”等完整要素，会形成实现与产品口径不一致。
  Evidence: `mapOverlays.ts:9-15` 标记 T7 后回填；`demo/README.md:146-150` 地图要素说明里仍包含“封道点”等表述；`mapOverlays.test.ts:38-42` 明确断言本轮不生成 `wind/controlZone/closure`。
  Modification advice: 在 README 或产品验收说明中标记这三类为“待 T7/后续版本”，或者补齐从当前聚焦事件预案措施参数回填地图的逻辑，并补充对应测试。
