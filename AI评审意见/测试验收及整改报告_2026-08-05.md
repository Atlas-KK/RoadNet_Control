## 4. 问题、整改与复验

| 编号 | 问题 | 影响 | 整改措施 | 复验结果 |
|---|---|---|---|---|
| R-01 | 高德 JS API 首次脚本加载失败时，模块级 `loadingPromise` 会保留 rejected 状态。 | 瞬时网络恢复后，组件再次挂载仍会复用失败结果，无法发起新的地图加载请求。 | 在 `script.onerror` 中清空 `loadingPromise`；新增 `amapLoader.test.ts`，验证失败后第二次调用会重新创建脚本请求。 | 通过；专项回归用例通过。 |
| R-02 | README 未记录本轮可复现的验收口径及 PowerShell 下的 `npm.ps1` 执行限制。 | 使用者难以复现验收，也可能误判 npm 命令失败为项目故障。 | 增加“最近一次测试验收”章节，给出 `npm.cmd` 命令、结果和整改说明。 | 通过；文档已同步。 |
| R-03 | 地图加载的失败重试意图缺少就近说明。 | 后续维护容易误删关键状态复位逻辑。 | 在高德加载器与对应测试中补充中文注释，解释浏览器异步事件时序与重试目的。 | 通过；注释已随代码提交。 |

## 6. 遗留边界与后续建议

- 目前未引入独立的浏览器端 E2E 测试框架；正式上线验收前应补充 Playwright 或 Cypress，覆盖事件上报、审计导出、配置弹窗、监控抽屉及不同分辨率布局。
- 高德 Key、安全密钥、域名白名单和公网访问依赖目标部署环境，应在目标环境完成实际接入验证。
- 生产环境不得把地图安全密钥或 LLM API Key 打包进前端；应通过受控服务端或网关代理提供能力。
