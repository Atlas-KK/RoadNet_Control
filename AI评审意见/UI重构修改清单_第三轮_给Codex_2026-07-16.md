### T2【事故等级】新增分级引擎并接入显示与排序

**新建**：`src/engine/severity.ts` + `src/engine/severity.test.ts`

1. 导出：
   ```ts
   export type Severity = '特别重大' | '重大' | '较大' | '一般';
   export interface SeverityInput {
     lanesTotal: number; lanesClosed: number;
     casualties?: number; hazmat?: boolean;
     inTunnel: boolean;      // 由 data/network.ts 的 tunnelAt(road, kp) 判定后传入
     congested: boolean;     // 流模型结论
   }
   export interface SeverityResult { level: Severity; rank: number; reasons: string[] }
   export function assessSeverity(input: SeverityInput): SeverityResult;
   export const SEVERITY_META: Record<Severity, { rank: number; color: string; label: string }>;
   ```
2. **判定规则（初值，按顺序短路，禁止自行发明）**：
   - `特别重大`（rank 0）：`hazmat && inTunnel` ｜ `casualties >= 10`

4. **测试 ≥4 条**：危化品×隧道→特别重大；全幅占道→重大；占道 2/3→较大；单车道占用且不拥堵→一般。

### T3【模拟事件源】并发上限 10 + 只产较大及以上

**文件**：`src/components/RuntimeBar.tsx`

**问题**：现有 `setInterval(..., 12000)` **无任何并发上限判断**，无脑生成（实测导致 48 起活跃、231 项待办、185 项超时），违反 SRS FR-A2「上限并发 8」。

**要求**：
1. 新增模块级常量 `const SIM_MAX_CONCURRENT = 10;`。
2. 每个 tick 生成前先读活跃事件数：`useStore.getState().events.filter(e => !e.finalized && !e.falsePositive).length`（**用 `getState()` 读，不要把 events 放进 effect 依赖**，否则每次事件变化都会重建定时器）。`>= SIM_MAX_CONCURRENT` 时**跳过本次生成**（定时器继续跑，不关闭）。
3. **只产「较大及以上」**：生成参数后先用 `assessSeverity` 预评，若为 `一般` 则重新随机，**最多重试 5 次**，仍为 `一般` 则跳过本次 tick（禁止死循环）。
4. 生成参数调整为可产出较大及以上：`lanesClosed` 取 `2 + Math.floor(Math.random()*2)`（2–3，配合 `lanesTotal:3` 即 ≥2/3 占道）；`casualties` 以 25% 概率取 1–2；`hazmat` 以 10% 概率为 true。
