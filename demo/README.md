# 路网综合管控智能体运行版

本项目是面向高速公路运行监测与应急处置的前端运行工作台，围绕“事件接入、事件归并、图谱推理、交通流计算、预案生成、人工复核、执行跟踪、审计留痕”构建可交互的业务闭环。

当前路网、桩号、设备和资源仍为模拟数据，仅用于产品验证和研发联调，不作为导航、测绘或生产调度依据。

## Arco 视觉规范

前端视觉以 [Arco Design System Community Copy](https://www.figma.com/design/Ef3hwy64Oam0J7ROoh4ZWX/Arco-Design-System--Community---Copy-?node-id=115962-128330&m=dev) 为参考，并读取其中 Card 组件节点 `120463:106317` 作为实现基线。

- 主色：`#4080FF`；主文字：`#1D2129`；次级文字：`#4E5969`；分隔线：`#E5E6E8`。
- 字体：中文以 `PingFang SC` 优先、英文以 `Nunito Sans` 优先，数值统一使用等宽字体并启用等宽数字。
- 卡片：白色卡面、`8px` 圆角与 `#E5E6E8` 细边框；常规业务卡片取消装饰性阴影，标题区统一 `48px` 高度与 `16px` 水平内边距。
- 控件：按钮、输入框与标签统一 `4px` 圆角，采用 `8px` 间距体系；操作图标统一 `14px` 对齐，焦点态使用主色描边，浅蓝色用于选中和反馈状态。
- 工作台：四列主布局使用 `12px` 栅格间距，地图保留深色地理信息底图以维持道路、拥堵和资源图层的辨识度。

## 主要能力

- 顶部一级 Tab 在“事件监测”和“智能管控”之间切换，默认进入“事件监测—视频事件监测”；两个模块的数据和临时界面上下文相互隔离。
- 事件监测模块提供视频事件卡片、组合筛选、工作指标、详情与证据、人工核实、L1～L4 分级、GIS 基础态势、严重事件接管、管控状态回写、权限校验、审计和服务降级演练。
- 事件监测业务数据使用独立 IndexedDB 仓储，IndexedDB 不可用时会明确降级为内存模式；模拟事件、证据和 GIS 点位均显示“模拟”标识。
- 事件上报、事件归并和多事件分诊；事件上报弹窗支持将原始接报文本通过 Qwen 结构化回填为道路、桩号、事件类型、车道占用和流量等字段。随机模拟事件源已移除，演示事件统一通过五个演示案例或人工上报进入系统。
- 五步推理、条件求值、交通流计算、分流冲突裁剪和资源链推理；新事件接入后可自动生成图谱推理解释，帮助非专业人员理解每一步为什么成立。
- 推理详情每次打开都会从第一个节点自动播放，可暂停、前进、后退和重新播放，图谱会同步显示当前节点与已走过的路径。
- 计算过程锁定本次事件，先给出瓶颈通行能力、行驶密度、排队密度、回溯速度等指标的综合结论，再展示公式、代入、结果和参数来源。
- 预案 V1/V2 版本管理，支持继承、新增、撤销、降级和状态流转。
- 统一待办队列，支持措施确认、下发、打回、作废、证伪和超时升级。
- 五个可重复装载的运行模式演示案例：跨事件分流冲突、资源链式挤兑、条件组合风险跃迁、属性修正撤销传导、方案自引用重构；每案均将事件输入、环境快照、车流、封控、设备、资源路线和关键事实修正收敛为时间片脚本，推理结论统一由引擎实时生成。
- GIS 地图展示事故点、拥堵线段、队尾、摄像机、情报板、处置资源、团雾带、隧道、分流承接线，以及从当前预案参数回填的封道点、无人管制区和通风方向。
- GIS 支持“事件孪生地图”视图：聚焦当前事件后，基于雷视融合口径生成仿真车流、车辆轨迹尾迹、雷视覆盖区和涉事目标信息，并在孪生视图中生成态势讲解；进入该视角会自动启动模拟时钟，车辆图标和拥堵态势持续演变，态势讲解首次进入立即生成，之后每 30 秒按最新车流、队列和管控措施刷新。
- 管控措施下发后，分流、限速、封道和清障执行状态会回写交通响应模型；拥堵网格、地图拥堵线和仿真车流统一经历“增长→稳定→消散→恢复”阶段，队尾位置随模拟时钟收敛。
- 现场监控联动、拥堵网格、核心面板全屏、审计导出和数据集 JSONL 导出。
- 现场监控使用三张 16:9 真实感合成抓拍图作为演示占位，主画面与缩略图按同一摄像机事件连续切换；素材不代表真实生产视频流。
- 可选 DeepSeek/Qwen/Kimi/OpenAI 兼容 LLM 增强：覆盖事件接报结构化、预案文案增强、图谱推理解释和事件孪生态势讲解，输出经 schema 与白名单校验后才展示。

## 运行项目

### Windows 一键启动

双击 `demo/一键启动.bat`。

脚本会检查 Node.js、安装缺失依赖、启动 Vite 服务，并打开浏览器。在 Codex 桌面环境中，即使 Node.js 未加入系统 `PATH`，脚本也会自动使用 Codex 内置运行时。

### 命令行启动

环境要求：Node.js `^20.19.0` 或 `>=22.12.0`。

```bash
npm install
npm run dev
```

默认访问地址：

```text
http://127.0.0.1:5173
```

### 本地固定配置大模型 API Key

项目支持从 `demo/API KEY.txt` 自动同步 DeepSeek、Qwen、Kimi 的 API Key 到 `demo/.env.local`，避免每次打开页面后重复填写 Key。文件行格式示例：

```text
deepseek：sk-xxx
qwen：sk-xxx
kimi：sk-xxx
```

运行 `npm run dev` 前会自动执行 `npm run sync:llm-keys`；也可以手动执行同步。同步脚本是尽力而为：如果 `.env.local` 正被 Vite、编辑器或其他进程占用，脚本会提示警告、保留已有配置并继续启动，不会阻断演示页面。需要更新 `API KEY.txt` 时，先关闭占用 `.env.local` 的旧进程，再执行 `npm run sync:llm-keys`。同步后的 `.env.local` 可参考 `demo/.env.local.example`：

```env
VITE_LLM_PROVIDER=qwen
VITE_LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
VITE_LLM_MODEL=qwen-plus
VITE_LLM_TIMEOUT_MS=10000
VITE_LLM_API_KEY=sk-your-api-key
VITE_LLM_QWEN_API_KEY=sk-your-qwen-api-key
VITE_LLM_DEEPSEEK_API_KEY=sk-your-deepseek-api-key
VITE_LLM_KIMI_API_KEY=sk-your-kimi-api-key
```

读取优先级为：页面配置弹窗临时输入的 API Key > `demo/.env.local` 中当前模型类型对应的 `VITE_LLM_*_API_KEY` > 通用 `VITE_LLM_API_KEY`。端点、模型类型、模型版本和超时时间均可在页面配置弹窗中调整；选择 DeepSeek/Qwen/Kimi 时，“模型版本”会以下拉框展示对应可选版本。修改 `API KEY.txt` 或 `.env.local` 后需要重新启动 Vite 服务才会生效；真实 Key 不应写入源码文件或示例文件。

## 运行说明

系统启动后默认进入“事件监测”模块，可通过顶部一级 Tab 切换至“智能管控”。旧的 S0-S5 脚本回放数据已清理；智能管控演示案例通过运行模式的标准事件接入管道装载，与手工上报使用同一套归并、推理、预案、复核和审计逻辑。首次升级到五案例版本时，系统会自动清理旧版本地运行快照及其审计记录，左侧分诊列表默认保持为空。

### 事件监测模块

事件监测当前为前端 MVP 原型，覆盖八类 P0 事件：交通拥堵、交通事故、行人闯入、车辆逆行、车辆倒车、异常停车、火灾和抛洒物。视频事件监测是主视图，GIS 态势感知是独立二级视图。

- 点击事件卡片可打开视频核实、关联告警、事件信息、核实记录和关联处置详情；视频不可用时保留关键帧、算法信息和文字证据。
- 监测员可认领核实任务并提交确认、误报或持续观察；L4 误报、降级和持续观察需要班长复核。系统管理员无业务核实权限。
- 人工确认 L4 后按规则自动发起接管；满足复合条件的 L3 由监测员人工发起。接管只创建智能管控事件和待确认措施，不自动下发交通控制指令。
- “降级演练”只修改本地模拟依赖状态，用于验证视频、GIS、AI 辅助和智能管控故障处理，不代表生产服务状态。

本地模拟模式每次进入事件监测模块时都会幂等补齐 24 条待核实事件，八种类型各 3 条，并使用 24 张独立的写实模拟监控图片；即使页面已有专项场景或人工补报事件，也不会跳过默认数据补齐，已存在的默认事件则不会重复创建。默认展示全部类型，用户可按事件类型筛选。六个专项监测场景继续通过 `DemoMonitoringAdapter → 标准化 → Alarm/Receipt 原子持久化 → 聚合 → MonitoringEvent → Store/UI` 接入页面，加载时追加到默认数据，不再要求先清空。演示工具支持加载、暂停/继续、人工补报、恢复默认数据和清空监测数据；清空操作只清理事件监测 IndexedDB/内存投影，不影响智能管控运行态。最新验收边界见 `产品文档/事件监测模块_阶段11全量验收与交付报告_v0.2.md`。

事件监测演示操作：

1. 进入事件监测模块后直接查看 24 条默认事件；已有其他演示事件时系统自动补齐且不重复，选择事件类型可将结果缩小为对应类型。
2. 选择六个专项场景之一并填写非负整数 seed，点击“加载场景”；场景事件会追加到现有列表并使用独立运行批次 ID。
3. 使用“暂停/继续”控制专项场景消息时钟；核实 SLA 使用独立运行时间，不随场景暂停。
4. “人工补报”通过与视频 AI 告警相同的标准化入口生成待核实模拟事件。
5. 主动清空后本次运行不自动回填；点击“恢复默认数据”可重新加载 24 条默认事件。
6. 未提交核实表单按事件和用户保存在 `sessionStorage`，刷新后给出草稿恢复提示；成功提交核实结论后清除草稿。

运行工作流：

1. 在顶部“演示案例”下拉框选择案例并点击“加载”；加载会清空当前运行库、事件和审计记录，再按案例脚本顺序重建现场。
2. 也可以点击“上报事件”录入道路、桩号、车道占用、流量、伤亡、危化品等信息；还可以粘贴原始接报文本并点击“AI解析”，由 Qwen 结构化回填表单。
3. 系统完成事件归并、五步推理、预案生成和 GIS 联动。进入“事件孪生”后，案例一会保留 G56 侧翻并将 G65 分流由 G56 切换至 S204；案例二在 14:57 后才允许 W-01 从 K1180 转场；案例三按 23:40:18–23:58 推进危化品封控；案例四在 10:25 的检测证伪时生成 V2 并撤除危化品态势；案例五在 16:33 切换为 K1140→S204，并于 17:06 兑现队尾预测。
4. 在统一待办队列中确认、打回或作废措施；案例四可再次通过事件行的“属性修正”入口复演事实撤回。
5. 必要时进行事件证伪、属性修正或审计/数据集导出。配置 DeepSeek/Qwen/Kimi API Key 后，预案面板、图谱推理详情和事件孪生地图会展示经校验的 AI 增强结果；若已在 `demo/API KEY.txt` 或 `demo/.env.local` 写入 Key，页面会自动读取。

### 推理与计算查看

在统一处置时序中点击某条推理记录的“图谱·计算”，会打开推理详情：

- 左侧图谱每次打开详情都会按“事件实例 → 事件类型 → 演化风险 → 管控措施/资源”的顺序自动播放并逐个高亮节点。
- 弹窗顶部会展示“图谱推理解释”，用通俗语言说明本步推理、关键节点、推理依据和复核重点。
- 可使用“暂停”“上一步”“下一步”和“重新播放”控制查看节奏。
- 右侧计算过程只展示本次事件，不提供跨事件“全部事件”视图，避免多事件并发时误读。
- 计算区顶部展示交通流综合结论，综合瓶颈通行能力、行驶密度、排队密度、队尾回溯速度和实时排队长度；每张卡片继续保留公式、实际代入、结果和参数来源。
- 普通点击推理步骤仍保留整步高亮，适合快速查看；打开详情后才进入逐节点播放模式。

## GIS 地图说明

地图统一使用高德地图 JavaScript API 2.0。高德提供真实道路底图、缩放、拖动、2D/3D 视角和深浅样式；项目路网、设施、事件、资源与雷视孪生要素均通过高德原生 `Polyline`、`Marker`、`InfoWindow` 覆盖物绘制。点击左侧事件列表、地图事故点或摄像机点位会同步聚焦高德地图并触发对应联动。

地图要素包括：

- 事故点、队尾标记、拥堵线段和实时资源点。
- 摄像机、情报板、风机、风向传感器等路侧设备。
- 事件孪生地图中的仿真车辆、轨迹尾迹、雷视融合覆盖区和涉事目标。
- 分流承接线、团雾带、隧道、枢纽线等空间要素。
- 当当前聚焦事件的预案包含 `M_通风` 或 `M_全封` 时，地图会从措施参数中回填动态要素：
  - `M_通风.无人管制区` → 管制区带状图层。
  - `M_通风.排风方向` → 通风方向线。
  - `M_全封.封道执行落点` 或 `封道点计算值` → 封道执行点。
- 未聚焦事件或预案尚未生成时，不生成上述动态要素，避免回退为单一场景硬编码。
- 五个案例均采用与剧本绑定的时空状态：案例一的双事件队列和分流切换、案例二的资源占用与转场、案例三的风场/扩散带/静止排队、案例四的事实撤回和封控降级、案例五的提前分流与队尾兑现，均随模拟时钟在高德地图原生覆盖物中一致更新。

### 事件孪生地图

在 GIS 左上角点击“事件孪生”，地图会围绕当前聚焦事件生成雷视融合仿真车流：

- 车辆目标按事件车道数、占用车道数、断面流量、自由流速和排队回溯速度生成。
- 每个案例的事故上游车辆均按剧本中的行驶方向、队尾、速度与封控状态生成；全封阶段仅保留静止滞留和受控疏散车流，资源车辆只在其脚本转场窗口移动，禁止车辆穿越事故区。
- 每个目标保留稳定 ID、车型、速度、车道、状态、位置和轨迹尾迹，点击车辆可查看目标信息。
- 雷视覆盖区按当前事件影响范围生成，用于表达“目标级结构化数据可支撑这一段仿真”。
- 配置 Qwen API Key 后，孪生视图会生成“态势讲解”最新时间片，历史最多保留 12 条用于追溯；讲解面板固定展示最新生成内容，进入视角时立即生成，之后每 30 秒自动刷新一次，切离事件孪生视角后停止刷新。
- 态势讲解下方提供“事故点位实时车流监测”：每 30 秒采样瓶颈通行能力、行驶密度、排队密度和排队回溯速度，并以四条独立量纲的曲线展示最近 12 个样本；指标结合流模型、已下发管控与案例孪生时间片计算。
- 五个案例均包含“部分恢复→现场清撤→事件终报”终态：GIS 会清除事故点与拥堵带，处置队列保留“已完成·效果已回写”的措施记录，监测曲线会表现可用车道增加后的通行能力提升、密度下降和回溯速度归零。切换案例时，监测样本按案例脚本与事件起始时刻重新建立，不会混入上一案例数据。
- 终报会作为智能处置时序的最后一条绿色卡片生成，包含现场清撤结论、已完成措施数、瓶颈通行能力与行驶密度的处置前后对比，以及排队消散状态；终报同时写入审计记录。
- 当前版本为产品原型仿真数据，未接入真实雷达/相机结构化接口，不作为生产研判依据。

## 开发约定

- `components` 只组织交互和渲染，不重复实现交通流、资源位置等业务算法。
- 领域对象定义放入 `domain`；算法放入 `engine`；地图共享转换放入 `gis`。
- 新增地图业务规则时，优先修改 GIS 共享模型和高德覆盖物适配器，确保空间状态与业务推理一致。
- 新增纯函数必须补充 Vitest 用例。
- 不在组件中硬编码外部接口密钥、生产电话号码或真实调度数据。

## 处置指令回执与基础设施联动（2026-08-08）

统一处置时序中的操作项被确认后，会生成仅用于演示的下发回执。回执覆盖系统、人员和设备三类目标：

- 系统和人员目标显示接收确认及模拟耗时；
- 设备目标如处于离线状态，回执标记为失败且不会改变设备展示状态；
- 全幅封道、车道封闭、分流诱导和隧道通风等成功指令，会同步更新基础设施网格图与 GIS 地图；

该能力复用现有模拟数据，不会调用真实的诱导发布、信号控制、人员调度或设备控制接口。

## 态势感知简报降级机制（2026-08-11）

- 孪生态势简报调用外部 LLM 时，若兼容端点拒绝 `response_format`，系统会自动移除该字段重试一次，并保留服务端返回的失败详情用于排查。
- 外部模型配置缺失、调用超时、HTTP 400 或输出校验不通过时，不再停留在“简报未生成”；系统会以当前模拟事件、交通模型、门架读数和已确认处置状态生成“本地规则引擎”简报。
- 本地简报与 AI 简报采用相同数据模型、时间片历史和面板展示能力，可正常继续按 30 秒刷新；其数据说明明确标注为模拟与模型结果，不替代现场实况。

## 常见问题

### 启动时报 `EPERM ... node_modules/.vite/deps`

先关闭旧的 Vite/Node 启动窗口，再重新双击 `一键启动.bat`。启动脚本使用独立缓存目录，可规避 Windows 锁定默认 Vite 缓存文件的问题。

### GIS 地图为空白

- 先按 `Ctrl+F5` 强制刷新，确认 `.env.local` 中已配置高德 Web JS API Key 与安全密钥。
- 检查浏览器是否可访问 `https://webapi.amap.com`，并确认高德控制台的域名白名单包含当前本地地址。
- 浏览器控制台若提示 Key 或安全密钥错误，请重新核验高德控制台配置；不要把安全密钥提交到源码。

### 页面布局拥挤

建议使用 1920×1080 分辨率和浏览器 100% 缩放，也可以使用各面板全屏按钮单独查看。
